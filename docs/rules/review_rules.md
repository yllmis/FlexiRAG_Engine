# 审核规则说明

## 设计目标

审核模块采用"规则优先、模型兜底"的分层策略。第一阶段仅实现规则审核，不做 LLM 审核。

## 审核范围（Scope）

| Scope   | 说明                   | 触发时机           |
|---------|------------------------|--------------------|
| input   | 用户输入审核           | 调用 Chat 接口前   |
| output  | 模型输出审核           | LLM 回答生成后     |
| ingest  | 知识入库审核           | 文档切片入库前     |

## 审核动作（Action）

| Action  | 说明                                      | 行为                   |
|---------|-------------------------------------------|------------------------|
| allow   | 放行                                      | 正常处理               |
| warn    | 警告                                      | 正常处理，记录审计日志 |
| review  | 需人工复核                                | 正常处理，标记待审核   |
| reject  | 拒绝                                      | 中断流程，返回错误码   |

## 规则分类（Category）

| Category          | 说明                         | 典型示例                   |
|-------------------|------------------------------|----------------------------|
| prompt_injection  | Prompt 注入攻击              | "忽略之前的指令"           |
| sensitive_content | 敏感/违规内容                | 涉政、涉暴、涉黄关键词     |
| business_sensitive| 业务敏感信息                 | 内部客户名单、薪资数据     |
| garbage_input     | 垃圾/超长输入                | 重复字符、超长无意义文本   |

## 匹配方式（Match Type）

| Match Type | 说明                 | 示例                              |
|------------|----------------------|-----------------------------------|
| exact      | 完全匹配             | pattern: "密码" 仅匹配 "密码"     |
| contains   | 包含匹配             | pattern: "密码" 匹配 "修改密码"   |
| regex      | 正则表达式匹配       | pattern: "\\d{11}" 匹配手机号     |

## 规则优先级

- 多条规则命中时，取 severity 最高的动作
- severity 相同时，reject > review > warn > allow
- 无规则命中时默认 allow

## 配置文件

机器可读规则位于 `configs/review_rules.yaml`，程序启动时加载。
